# BrainSharp.Xml 1.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix issue #1, optimize comparison, make file parsing truly async, announce the 2.0.0 static-class break with `[Obsolete]`, and correct the NuGet URLs.

**Architecture:** `CompareNodes` in `Xml.cs` keeps its recursive shape but matches child elements in two passes (exact `XNode.DeepEquals`, then same local name) over a per-call pool of unpaired elements. Everything else is additive.

**Tech Stack:** net8.0, NUnit, System.Xml.Linq.

**Spec:** `docs/superpowers/specs/2026-11-15-xml-1.1.0-fixes-design.md`

## Global Constraints

- Public method names and signatures of 1.0.7 stay source compatible (new parameters only as optional trailing ones).
- The existing 155-difference tests (`products1.xml` vs `products2.xml`) must stay green.
- Do not edit vendored logic under `src/BrainSharp.XmlDiff/XmlDiffPatch` or `XmlDiffView`; only `BrainSharp.XmlDiff.csproj` metadata.
- No `Co-Authored-By` or any Claude attribution in commit messages; the author signs commits.
- Do not run `dotnet nuget push`. Do not bump the `BrainSharp.XmlDiff` PackageReference (stays 1.0.1 until 1.0.2 is on nuget.org).
- Run commands from `src/BrainSharp.Xml/`.
- `PackageProjectUrl` / `RepositoryUrl` value: `https://github.com/VasilisPlavos/BrainSharp.Xml`.

## Review Focus

- Two identical sibling elements in doc1 and one in doc2: expect exactly 1 "Missing child node on second xml" (Task 1).
- Same siblings in a different order: expect 0 differences (Task 1).
- Same local name in different namespaces: still matched by fallback, as documented in CLAUDE.md (Task 1).
- Document with no root (`XDocument` created empty): clear `ArgumentException`, not `NullReferenceException` (Task 2).
- Async parse of a missing file: throws `FileNotFoundException`; cancelled token throws `OperationCanceledException` (Task 2).

### Task 1: Two-pass child matching (issue #1) and cheaper comparison

**Files:**
- Modify: `src/BrainSharp.Xml/BrainSharp.Xml/Xml.cs` (`CompareNodes`, `FindNode`)
- Test: `src/BrainSharp.Xml/BrainSharp.Xml.Test/XmlTests.cs`

**Interfaces:**
- Produces: `private static List<string> CompareNodes(XElement node1, XElement node2, bool ignoreNodeValues = false)` (same signature, new matching); `FindNode` is removed.

- [ ] **Step 1: Write failing tests** in `XmlTests.cs`, using `Xml.ExplainDifference(string, string)`:
  - `ExplainDifference_FirstHasExtraSibling_ReturnsOne`: `<r><a id="1"/><a id="2"/></r>` vs `<r><a id="2"/></r>` → `Count == 1`.
  - `ExplainDifference_SecondHasExtraSiblingOfSameName_ReturnsOne`: reverse of the above → `Count == 1` and the message starts with `Missing child node on first xml`.
  - `ExplainDifference_ReorderedSiblings_ReturnsZero`: `<r><a id="1"/><b/></r>` vs `<r><b/><a id="1"/></r>` → `Count == 0`.
  - `ExplainDifference_DuplicateSiblings_ReportsOnlySurplus`: `<r><a/><a/></r>` vs `<r><a/></r>` → `Count == 1`.
  - `ExplainDifference_SameNameDifferentNamespace_StillMatched`: `<r><a xmlns="urn:x"/></r>` vs `<r><a xmlns="urn:y"/></r>` → `Count == 0`.
- [ ] **Step 2: Run** `dotnet test --filter "FullyQualifiedName~XmlTests"`. Expected: the new extra-sibling tests and `ExplainDifferenceFromFile_TwoFiles_XDifferences("products3a.xml", ...)` FAIL.
- [ ] **Step 3: Rewrite the child-comparison section of `CompareNodes`.** Build `var pool = childNodes2.OfType<XElement>().ToList()` once. Pass 1: for each element of doc1, find an exact match in the pool with `XNode.DeepEquals`, remove it (swap-remove or index removal), record the pair. Pass 2: group the remaining pool by `Name.LocalName` into `Dictionary<string, Queue<XElement>>`; each unpaired doc1 element dequeues a same-name partner or reports `Missing child node on second xml: {Name}`. Exact pairs need no recursion (zero differences); fallback pairs recurse via `CompareNodes`. Every element left in any queue reports `Missing child node on first xml: {Name}`. Message formats stay exactly as today. Keep attribute comparison, replacing the `FirstOrDefault`/`Any` lookups with `TryGetValue`/`ContainsKey` on the dictionaries. Do not call `.ToList()` on node lists that are only enumerated once.
- [ ] **Step 4: Run** `dotnet test`. Expected: all tests PASS, including the 155 cases and `products3a/3b` (== 1). Remove the `// TODO: This should return 1. Fix it` comment from that `TestCase`.
- [ ] **Step 5: Commit** `fix: match child elements in two passes (#1)` (no attribution lines).
