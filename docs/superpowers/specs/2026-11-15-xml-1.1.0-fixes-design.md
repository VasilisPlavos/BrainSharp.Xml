# BrainSharp.Xml 1.1.0: bug fix, optimizations, deprecation path

## Intent
The package is old and published on nuget.org. The author wants the bug in issue #1 fixed, general optimizations, and the wrong repository URL on the NuGet page corrected, without breaking existing 1.x consumers. The one unavoidable break (`Xml` becoming a static class) is announced now with a warning and delivered in 2.0.0.

## Goals
- Fix issue #1: `ExplainDifference*` must report 1 difference for `products3a.xml` vs `products3b.xml`.
- Make comparison cheaper (no repeated subtree serialization, no O(n^2) list removals).
- Make `ParseFromFileAsync` truly async.
- Correct `PackageProjectUrl` / `RepositoryUrl` in both csproj files.
- Warn users of `new Xml()` that the class becomes static in 2.0.0.

## Non-goals / anti-goals
- No change to public method names or signatures in 1.1.0.
- No change to the output for inputs that were already compared correctly (the 155-difference test must stay green).
- No edits to the vendored XmlDiffPatch/XmlDiffView logic, only to `BrainSharp.XmlDiff.csproj` metadata.
- No publishing; the author runs `dotnet nuget push` and signs the commit.

## Constraints
- net8.0, nullable and implicit usings on.
- `BrainSharp.Xml` references `BrainSharp.XmlDiff` as a NuGet package (1.0.1), so XmlDiff metadata fixes only reach nuget.org after XmlDiff is republished (1.0.2) and the reference is bumped.
- Commits carry only the author's signature (no Co-Authored-By).

## Approaches considered (deprecation)
- **A. Explicit `[Obsolete]` public constructor (chosen).** Warns only `new Xml()` callers, static calls are untouched; 2.0.0 deletes the constructor and adds `static`.
- B. New static class plus obsolete wrapper `Xml`: duplicate API, more upkeep for a break that only affects `new`.
- C. README note only: no signal in consumers' builds.

## Design
1. **Matching (issue #1).** In `CompareNodes`, match child elements in two passes: (1) pair every child that has an exact structural match (`XNode.DeepEquals`), (2) pair each remaining child with a remaining element of the same local name, in order. Anything still unpaired in doc1 is "Missing child node on second xml", anything unpaired in doc2 is "Missing child node on first xml". The reverse check uses the unpaired list, so surplus elements in doc2 are now reported even when doc1 has an element of that name.
2. **Performance.** Replace `ToString()` comparison with `DeepEquals`, group the remaining candidates by local name (dictionary of queues) instead of repeated `FirstOrDefault` and `List.Remove`, compare attributes through the dictionaries directly, and avoid materializing node lists more than once.
3. **Async.** `ParseFromFileAsync` uses `XDocument.LoadAsync` over a `FileStream` opened with `useAsync: true`; add an optional `CancellationToken` parameter (additive, source compatible).
4. **Robustness.** Clear `ArgumentException` when a document has no root; remove unused usings and nullable warnings.
5. **Deprecation.** `[Obsolete("Xml will become a static class in 2.0.0. Call the static methods directly.")] public Xml() { }`.
6. **Metadata.** Both csproj files point `PackageProjectUrl` and `RepositoryUrl` to `https://github.com/VasilisPlavos/BrainSharp.Xml`. `BrainSharp.Xml` version 1.1.0 with release notes; `BrainSharp.XmlDiff` version 1.0.2 and `BrainSharp.Xml` references it. (My call: bump the reference once 1.0.2 is on nuget.org; until then the reference stays at 1.0.1.)
7. **Tests.** Existing `products3a/3b` case becomes green. Add: doc2 has a surplus element of a name doc1 also has (expects 1 "missing on first"), reordered siblings (0 differences expected by exact match), and a real async test comparing sync and async parsing. Make fixture paths portable with `Path.Combine`.
